## 주장 상태와 검토 상태

주장 상태와 독립 검토 여부를 따로 기록합니다.

| 주장 상태 | 의미 |
| --- | --- |
| 증명됨 | 명시한 가정 아래 완결된 증명을 노트에 제시함 |
| 추측 | 일반적인 참·거짓이 아직 결정되지 않음 |
| 계산 관찰 | 명시한 입력 범위에서만 계산으로 확인함 |
| 반박됨 | 원래 조건을 만족하는 반례를 제시함 |

독립 검토 상태는 `대기`, `수정 필요`, `통과`를 사용합니다. `통과`에는 검토 문서 링크와 검토 대상의 날짜 또는 버전이 필요합니다. 작성자가 자기 증명을 점검한 일은 독립 검토로 세지 않습니다. 공개할 때는 검토 대기 여부도 함께 표시합니다.

문헌 관계는 `알려진 결과`, `재유도`, `신규성 미확인` 등으로 별도 기록합니다. 스스로 증명했다는 사실만으로 새로운 정리라고 부르지 않습니다.

## 성과 점수

[성과 점수 기준](Scoring.md)에 따라 노트의 새로운 수학적 기여를 잠정 평가합니다. 점수·근거·변경 이력은 각 연구 폴더의 `meta.json` 한 곳에서 관리합니다. [웹뷰어](Viewer.md)가 이를 읽어 점수순으로 정렬하므로 Markdown 목록의 순서를 맞출 필요는 없습니다. 설명의 완성도, 신규성, 정확성 검토는 구별합니다. 독립 에이전트 검토 통과가 자동으로 높은 성과 점수나 학계의 인정을 뜻하지 않습니다.

## 파일과 링크

- 연구 폴더: `research/YYYY-MM-DD-topic-short-id/`.
- 기본 문서: `note.md`. 계산 코드와 데이터는 같은 폴더에 보관합니다.
- 문서 간 링크는 `[설명](../다른폴더/note.md)` 형태의 상대 경로를 씁니다.
- 수식은 인라인 `$...$`, 별도 줄 `$$...$$`를 사용합니다. 렌더링은 최종 위키 도구의 수식 지원에 따릅니다.
- 제목은 사람이 읽기 쉽게, 경로는 짧고 안정적으로 유지합니다.
- 외부 자료는 원문 링크와 확인 날짜를 기록합니다. 자체 유도만 사용했다면 그렇게 표시합니다.

## 연구 한 건의 흐름

1. 질문과 정의역을 명시합니다.
2. 작은 사례와 경계 사례를 확인합니다.
3. 패턴을 주장으로 적고 증명 또는 반례를 찾습니다.
4. 실패한 시도와 한계를 기록합니다.
5. 다른 에이전트가 원문의 가정을 기준으로 검토합니다.
6. 조율자가 결과를 분류하고 위키 색인에 연결합니다.

탐구 단계에서도 색인에 연결할 수 있습니다. 이 경우 추측·미검토 상태가 명확히 보여야 합니다. 논증을 수정했다면 이전 검토 통과를 자동으로 승계하지 않습니다.

## 계산의 재현성

실행 명령, 환경, 탐색 범위와 출력을 남깁니다. 실수 근사를 사용하면 오차와 허용 기준을 적습니다. 난수를 쓰면 시드를 남깁니다. 데이터가 크면 생성법과 요약만 보관하고 불필요한 대용량 파일을 추가하지 않습니다.
